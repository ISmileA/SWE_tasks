# Отчёт по серии заданий 1 (с1сз1)

Прикладные задачи на готовых моделях машинного обучения.

Работа выполнялась командой. Своё обучение моделей не проводилось: для каждой задачи взяты уже опубликованные веса и написан вывод. Ниже коротко зафиксированы постановка, выбор библиотеки и модели, из чего модель училась, какие у неё метрики и как устроен запуск.

## 1. Что делали

По заданию нужно закрыть четыре типа данных и использовать минимум два фреймворка. Взяты три: Hugging Face, TensorFlow Hub и PyTorch.

| Задача | Фреймворк | Модель |
| --- | --- | --- |
| Тональность короткого русского текста | Hugging Face Transformers | `cointegrated/rubert-tiny-sentiment-balanced` |
| События в аудиозаписи | TensorFlow Hub | YAMNet |
| Класс объекта на фото | PyTorch, torchvision | ResNet-18 |
| Рамки объектов на видео | Hugging Face Transformers | `facebook/detr-resnet-50` |

Тональность оставлена как задача, из которой потом проще всего сделать API: на вход строка, на выход JSON. Видео и картинки принимают файлы и на CPU работают тяжелее.

Примеры в основном чужие, из официальных туториалов. Фото собаки взято из материалов PyTorch Hub, запись мяуканья — из туториала TensorFlow по YAMNet. Ролик для детекции собран из этого же фото: короткий наезд, около 2,5 секунд. Так проверяется проход по кадрам, и в кадре есть класс `dog`, который модель знает.

## 2. Техническое задание

**Текст.** На вход одна или несколько непустых русских фраз. На выход класс `negative`, `neutral` или `positive`, подпись по-русски и вероятности всех трёх классов. Текст длиннее 512 токенов обрезается. Готово, если похвала, жалоба и нейтральная фраза получают ожидаемые классы.

**Аудио.** На вход PCM WAV. Частота приводится к 16 кГц, стерео схлопывается в моно. На выход топ событий и их средние вероятности. Это классификация звуков, расшифровки речи в текст нет. Короткая запись дополняется тишиной до секунды, потому что окно модели около 0,96 с.

**Изображение.** На вход файл картинки, с учётом поворота EXIF. На выход топ-5 классов ImageNet. Своих категорий нет, только те, на которых училась сеть.

**Видео.** На вход ролик, порог и шаг по кадрам. На выход новый файл с рамками и сводка, какие классы нашлись. Детектор смотрит отдельные кадры. Связки объекта между кадрами нет: между ключевыми кадрами просто держится последняя рамка.

## 3. Тональность текста

### Библиотека

Hugging Face удобен тем, что веса, токенизатор и имена классов лежат под одним именем модели. Карточка на сайте сразу показывает качество на русских корпусах, выбор можно было сверить до запуска. Тот же пакет потом использовался для детекции на видео, способ загрузки похожий.

Модель вызвана напрямую, через токенизатор и `BertForSequenceClassification`. Так в ответе остаётся вероятность всех трёх классов. Готовый `pipeline` на этих весах отдаёт только победителя.

### Модель

В основе BERT (Devlin et al., 2019): кодировщик-трансформер читает текст в обе стороны. Фраза режется на подслова, в начале стоит токен `[CLS]`, по его вектору линейный слой выдаёт три числа, softmax переводит их в вероятности. Веса уже дообучены, при запуске градиент не считается.

Взята маленькая версия, не полный BERT. По конфигу на Hugging Face: 3 слоя, скрытый размер 312, 12 голов внимания, словарь около 30 тысяч, классы 0 — negative, 1 — neutral, 2 — positive. Файл весов примерно 47 МБ, в загруженной сети около 11,8 млн параметров. Для будущего API это важнее, чем максимальное качество: на CPU ответ получается быстро. На сложном корпусе LINIS macro-F1 у этой модели всего 0,50, это ограничение размера.

### Датасет

Модель дообучали на подборке русских корпусов, которую собирал Сметанин. Метки свели к трём классам и выровняли источники, чтобы один корпус и один класс не задавили остальные. Один пример в таком наборе — короткий текст и одна метка. В контроле у авторов фигурируют SentiRuEval2016 (банки и телеком), новости, LINIS, mokoron, RuReviews, RuSentiment. Сами корпуса в репозиторий не клались.

Задача по смыслу близка к разбору отзывов: по короткой фразе видно отношение к продукту (Giannakis, Dubey, Yan et al., 2020).

### Метрики

На карточке модели указан macro-F1 на сбалансированных контрольных частях. Это среднее F1 по трём классам, без перекоса в сторону самого частого.

| Источник | Macro-F1 |
| --- | --- |
| SentiRuEval2016, банки | 0,83 |
| SentiRuEval2016, телеком | 0,74 |
| RuReviews | 0,72 |
| RuSentiment | 0,67 |
| новости с Kaggle | 0,66 |
| LINIS | 0,50 |
| mokoron | 0,98 |

Полный пересчёт по этим корпусам не делался. Локально проверены три понятные фразы, результаты в разделе 7.

### Как сделано

Код в `ml_tasks/text_sentiment.py`. Модель поднимается при первом вызове и остаётся в памяти. Строки дополняются до одной длины и обрезаются до 512 токенов. Класс с наибольшей вероятностью пишется как ответ, рядом лежит всё распределение.

На проверочных фразах сам вывод занял около 15 мс. Загрузка весов с диска — около 2,4 с. Для сервиса модель имеет смысл поднимать один раз при старте.

## 4. Аудио

### Библиотека

Для звука взят TensorFlow Hub, модель YAMNet: `https://tfhub.dev/google/yamnet/1`. На вход подаётся волна `float32` от −1 до 1, спектрограмму отдельно считать не нужно, она считается внутри SavedModel. Имена 521 класса тоже лежат в файлах модели.

Отдельный фреймворк здесь нужен по условию задания. Текст и видео уже на Hugging Face, звук специально посажен на TensorFlow.

С установкой вышла заминка. На Python 3.14 колеса TensorFlow для Windows не нашлись. Окружение собрано на Python 3.13, версия TensorFlow 2.21. Видеокарты на машине нет, PyTorch ставился CPU-сборкой, иначе `pip` тянет большой CUDA-пакет.

### Модель

YAMNet — это MobileNet по кускам спектрограммы (описание в репозитории TensorFlow Models, архитектура свёрток из MobileNet, Howard et al., 2017). Запись режется на окна примерно 0,96 с с шагом 0,48 с. На каждом окне сеть даёт 521 вероятности. Классы друг от друга не зависят: в одном куске могут быть и речь, и музыка, поэтому это не softmax на один правильный класс. В программе вероятности усредняются по окнам и берётся топ-5.

Узкий детектор команд вроде «yes/no/stop» был бы проще, но на обычной записи от него мало толку. YAMNet покрывает и речь, и бытовые звуки, и животных. Текста из аудио программа не получает.

Число параметров из загруженного объекта достать не удалось: у модели с Hub нет списка `variables`. В кэше файл весов около 15 МБ, то есть сеть небольшая. В отчёт точный подсчёт не выносился.

### Датасет

Обучение на AudioSet (Gemmeke et al., 2017), куски звука с YouTube. По описанию YAMNet это около 1,57 млн десятисекундных фрагментов на обучении и 20 366 фрагментов на контроле. В исходном AudioSet 527 классов, в модели остался 521. Пример датасета — фрагмент и набор слабых меток: событие где-то внутри клипа есть, границы по времени не размечены. Таблица AudioSet не скачивалась, на вход программе идёт только wav.

Демофайл `samples/miaow_16k.wav` — мяуканье, 16 кГц, моно, из туториала TensorFlow.

### Метрики

На контроле AudioSet авторы приводят balanced mAP 0,306, d-prime 2,318 и lwlrap 0,393. mAP выглядит скромно рядом с точностью ImageNet, но классов сотни и метки слабые, шкала другая. У себя проверялось только мяуканье: вверху списка должны быть кошка и животное.

### Как сделано

Код в `ml_tasks/audio_events.py`. WAV читается средствами TensorFlow, каналы сводятся в один, чужая частота пересчитывается линейно. Ответ усредняется по времени, короткая вспышка звука из-за этого немного теряется, зато по файлу получается одна оценка.

Запись на 6,7 с посчиталась примерно за 0,25 с, уже после загрузки модели. Загрузка самой модели заняла около 2,5 с.

## 5. Изображения

### Библиотека

PyTorch и torchvision. У весов `ResNet18_Weights.IMAGENET1K_V1` сразу есть предобработка, список из 1000 классов и опубликованная точность. Отдельно качать имена классов ImageNet не пришлось. Файл весов около 45 МБ.

### Модель

ResNet-18 (He et al., 2016) — свёрточная сеть с остаточными блоками: слой учит добавку к входу, за счёт этого глубокую сеть вообще получается обучить. Дальше глобальное усреднение и линейный слой на 1000 классов. В документации torchvision у этих весов около 11,7 млн параметров и 1,81 GFLOPs.

Картинка приводится к 224×224: меньшая сторона к 256, центральный кроп, нормировка как у ImageNet. ResNet-50 на тех же данных точнее, около 76% top-1, но тяжелее. На CPU для демонстрации хватило 18-й сети.

### Датасет

ImageNet-1K: порядка 1,28 млн картинок на обучении, 50 тысяч на контроле, 1000 классов. Один пример — изображение и один класс. В программе самого датасета нет, только веса и список названий.

### Метрики

По документации torchvision: top-1 69,8%, top-5 89,1%. Top-5 здесь заметно выше, поэтому в программу выводится пять классов, а не один. Пересчёт по всем 50 тысячам картинок не делался.

### Как сделано

Код в `ml_tasks/image_classification.py`. Картинка открывается через Pillow. Один проход, softmax, топ-5. На контрольном фото вывод занял около 50 мс, чтение уже скачанных весов — около 0,2 с.

## 6. Видео

### Библиотека

Снова Hugging Face, модель `facebook/detr-resnet-50`. Кадр готовит процессор библиотеки, рамки в пиксели переводит `post_process_object_detection`. Читает и пишет видео OpenCV, к выбору ML-фреймворка это не относится.

При первом запуске модель не собралась. Основа ResNet-50 у этого чекпоинта поднимается через пакет `timm`, без него Transformers останавливается с просьбой его поставить. После `pip install timm` загрузка прошла. В `requirements.txt` пакет дописан.

### Модель

DETR (Carion et al., 2020) ищет объекты одним трансформером. ResNet-50 строит карту признаков, декодировщик держит набор запросов (их 100) и для каждого выдаёт рамку и класс. Отдельного подавления пересекающихся рамок на выводе нет, это уже учтено при обучении.

На COCO у DETR с ResNet-50 средний AP 42,0. У авторов модели кадр считается быстро. На CPU в этой работе один кадр вышел около 1,5 с. Поэтому детектор вызывается не на каждом кадре. Модель не следит за объектом во времени, это покадровая детекция.

В загруженной сети около 41,5 млн параметров, файл весов порядка 160 МБ.

### Датасет

COCO 2017: около 118 тысяч картинок на обучении и 5 тысяч на контроле, 80 категорий объектов. У аннотации есть категория и рамка: левый верхний угол, ширина и высота. На выводе программа получает уже углы рамки в пикселях кадра.

### Метрики

С карточки модели и таблицы авторов: AP 42,0, AP50 62,4, AP75 44,2. Мелкие объекты находятся хуже (AP small около 20,5). На проверочном ролике собака крупная, это простой случай. Порог в программе 0,7, чтобы слабые рамки не забивали короткий ролик.

### Как сделано

Код в `ml_tasks/video_detection.py`. Кадры читаются по одному. Модель вызывается каждый 5-й кадр, на остальных рисуется последняя рамка. Это экономит время примерно в пять раз. На быстром движении рамка будет запаздывать. На медленном наезде в проверочном ролике это почти не видно. Если mp4 не открылся на запись, код пробует avi.

30 кадров посчитались примерно за 9 с. Из них сеть вызывалась 6 раз.

## 7. Что получилось при запуске

Запуск: `python -m ml_tasks demo`, CPU, Python 3.13. Цифры времени — уже после того, как веса скачались. Полный JSON лежит в `outputs/demo_results.json`.

Текст:

- «Прекрасный фильм, рекомендую всем друзьям» — positive, 0,994
- «Ужасное качество, больше никогда не куплю» — negative, 0,980
- «Сегодня вторник, занятие начинается в десять» — neutral, 0,967

Три фразы посчитались примерно за 15 мс.

Аудио, файл 6,7 с. Вверху списка Animal (0,71), Domestic animals, pets (0,51), Cat (0,42), Meow (0,20). Сумма не равна единице: у YAMNet у каждого класса своя вероятность. Пятым вылез Fowl с оценкой около 0,10, это лишняя слабая метка. Вывод занял около 0,25 с.

Фото: первый класс Samoyed, 0,885. Дальше с маленькой вероятностью Arctic fox и white wolf, потом снова породы Pomeranian и Great Pyrenees. Белая собака немного путается с похожими животными, но первый класс уверенный. Вывод около 50 мс.

Видео 1546×1212, 30 кадров. Класс dog на всех 6 ключевых кадрах, максимум 0,997. Файл `outputs/dog_detected.mp4` открывается, в нём те же 30 кадров.

## 8. API и тесты

Группа 11-411, Игнатьев Арсений и Николаева Полина. Вторая часть делалась той же командой.

Разделение такое. Игнатьев Арсений собрал HTTP-сервис: файл `main.py`, запрос и ответ через pydantic, вызов уже написанной `analyze_sentiment`. Николаева Полина написала тесты в `tests/test_api.py` и файл `.github/workflows/tests.yml`, чтобы pytest запускался при push. Запуск сервиса и тестов смотрели вдвоём. На API ушло больше времени у Игнатьева, на тесты и Actions — у Николаевой.

В API вынесена только тональность. На вход одна непустая строка, на выход метка, русское название и вероятность. Пустая строка не проходит проверку схемы, ответ 422. Видео и звук в этот сервис не ставились: там файлы и заметно большее время ответа.

Запуск локально:

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --reload
```

Проверка: `POST /predict/` с полем `text`. Корень `GET /` отвечает, что сервис жив.

Тесты повторяют три фразы из прогона первой части и отдельно проверяют пустой текст. Для них ставится pytest и httpx, они дописаны в `requirements.txt` рядом с fastapi и uvicorn.

На GitHub Actions тесты стартуют при каждом push. В рабочем окружении ставятся библиотеки самого API (FastAPI, transformers, CPU-сборка PyTorch, pytest). TensorFlow и OpenCV для этих тестов не нужны.

## 9. Вывод

Сделаны четыре задачи на готовых моделях, фреймворков три. Для текста взята маленькая русская BERT-модель: на отзывах macro-F1 около 0,72, на CPU ответ быстрый. Звук закрыт YAMNet из TensorFlow Hub. Картинки — ResNet-18, top-1 около 70%, top-5 около 89%. Видео — DETR с AP 42 на COCO, по кадрам и с шагом, потому что на CPU полный проход каждого кадра слишком долгий.

Основное время уходит на первую загрузку весов. Пока модель уже в памяти, текст и картинка считаются быстро, детекция на видео остаётся самой тяжёлой частью.
